Litmus Edge publishes device data to NATS topics. The Litmus Edge data source plugin subscribes to those topics and streams the values into Grafana panels as they arrive. This page installs the plugin, connects it to Litmus Edge, and shows live data in a panel.

## Install

### Before You Start

- Litmus Edge v3.16 or later. The tested series is 4.4.x (verified on 4.4.2).
- For the standalone image, Docker on a Linux amd64 or arm64 host with access to `litmusedge.azurecr.io`. Use host port `3000` or another free port. To run inside Litmus Edge, run Docker on the Litmus Edge host.
- For the plugin alone, Grafana v12.2 or later on Linux amd64 or arm64, shell access to its host or container, and permission to restart Grafana.
- A data point publishing to NATS. Grafana must be able to reach the NATS Proxy on TCP port `4222` by default. For an external connection, enable the NATS Proxy and [create an Access Account](https://docs.litmus.io/litmusedge/product-features/system/access-control/tokens/create-api-account) with read access to the topics you plan to stream, or use a message broker token with the same permissions.
- For topic discovery, [create a separate Litmus Edge API token](https://docs.litmus.io/litmusedge/product-features/system/access-control/tokens/create-api-token) and make sure Grafana can reach the Litmus Edge HTTPS endpoint (default TCP port `443`). The Access Account token for NATS does not authenticate topic discovery.

### Choose an Install Path

To add the plugin to a Grafana instance you already run, use the **Existing Grafana** tab and continue with the next section. To start a new Grafana with the plugin preinstalled, use the **litmus-grafana image** tab.

:::::Tabs
::::Tab{title="Existing Grafana"}
Install the plugin in your Grafana instance, then connect it to Litmus Edge. Continue with **Install the Plugin** below.
::::
::::Tab{title="litmus-grafana image"}
The `litmus-grafana` image includes the plugin and provisions the Litmus Edge data source. Docker pulls the image for your architecture from the Litmus registry. You do not need the Central plugin ZIP for this path.

To run Grafana inside Litmus Edge, run this command on the Litmus Edge host. Change the Docker gateway IP if your instance uses a different address. For topic discovery in either mode, export `EDGE_API_TOKEN` first.

```bash
docker run -d --name litmus-grafana -p 3000:3000 \
  -e EDGE_DOCKER_GATEWAY_IP=10.30.50.1 \
  -e EDGE_API_TOKEN \
  litmusedge.azurecr.io/litmus-grafana:0.2.1
```

To connect to an external Litmus Edge instance, replace the example URL and run the following command. Export `EDGE_ACCESS_ACCOUNT_TOKEN` in your shell first.

```bash
docker run -d --name litmus-grafana -p 3000:3000 \
  -e EDGE_EXTERNAL=true \
  -e EDGE_URL=https://litmus-edge.example:443 \
  -e EDGE_NATS_PROXY_PORT=4222 \
  -e EDGE_ACCESS_ACCOUNT_TOKEN \
  -e EDGE_API_TOKEN \
  litmusedge.azurecr.io/litmus-grafana:0.2.1
```

Use a Litmus Edge address that resolves from the Grafana container. If Litmus Edge also runs in Docker and you use its container name, add `--network <edge-network>` to `docker run`, replacing `<edge-network>` with its existing Docker network. If port `3000` is taken, use a free host port, for example `-p 3001:3000 -e GF_SERVER_ROOT_URL=http://localhost:3001` in place of `-p 3000:3000` for local access.

Open Grafana on the published port (`http://localhost:3000` by default). Sign in with `admin` / `admin` and follow the prompt to change the password. Skip to **Verify Your Setup**.

| Name | Required | Default | Description |
| --- | --- | --- | --- |
| `EDGE_EXTERNAL` | No | `false` | Set to `true` for a remote Litmus Edge instance. |
| `EDGE_DOCKER_GATEWAY_IP` | No | `10.30.50.1` | Docker gateway IP used inside Litmus Edge. |
| `EDGE_URL` | External only | None | Litmus Edge HTTPS URL, hostname, or `host:port`. The port here is for the API, not NATS. |
| `EDGE_NATS_PROXY_PORT` | No | `4222` | NATS Proxy port for live streaming. |
| `EDGE_ACCESS_ACCOUNT_TOKEN` | External only | None | Access Account token with NATS Proxy read access. |
| `EDGE_API_TOKEN` | No | None | Litmus Edge API token for DeviceHub topic discovery in either mode. |

### Install the Plugin

1. Download `litmus-edge-datasource-0.2.1.zip` from [Litmus Grafana downloads in Central](https://portal.litmus.io/accelerators/litmus-grafana?tab=downloads).
2. Copy the ZIP to the Grafana host or container and run the following command there. If you use a custom Grafana plugins directory, replace the default path.

   ```bash
   unzip litmus-edge-datasource-0.2.1.zip -d /var/lib/grafana/plugins/
   ```

3. Restart Grafana. The **Litmus Edge** data source type appears when you add a data source.

:::hint{style="warning"}
The release plugin is signed for `http://localhost:3000`, `http://localhost:3001`, `http://localhost:3002`, `http://localhost:8080`, and `http://localhost:8443`. Set Grafana `root_url` to the matching URL before restarting. To test an unsigned local build, set `GF_PLUGINS_ALLOW_LOADING_UNSIGNED_PLUGINS=litmus-edge-datasource` before restarting.
:::

### Connect to Litmus Edge

To add the data source, follow [Add a data source](https://grafana.com/docs/grafana/latest/datasources/add-a-data-source/) in the Grafana documentation and select **Litmus Edge**. Then enter the connection details for your setup. To configure the data source from a file instead, use the provisioning YAML in the same tab.

:::::Tabs
::::Tab{title="Grafana inside Litmus Edge"}
Leave **Remote Connection** off and set these fields:

| Field                      | Description                                                                                                                                                                    |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Edge Docker Gateway IP** | IP address Grafana uses to reach Litmus Edge. Default: `10.30.50.1`. Change it if your Litmus Edge instance uses a different Docker gateway IP. The plugin does not detect it. |
| **API Token**              | Optional. Enables topic discovery in the query editor.                                                                                                                         |

To provision the data source, save this file in the Grafana provisioning directory:

```yaml
apiVersion: 1
prune: true

datasources:
  - name: Litmus Edge
    type: litmus-edge-datasource
    access: proxy
    editable: true
    jsonData:
      externalEdge: false
      gatewayIp: $EDGE_DOCKER_GATEWAY_IP
    secureJsonData:
      apiToken: $EDGE_API_TOKEN
```

::::
::::Tab{title="External Litmus Edge"}
Turn on **Remote Connection** and set these fields:

| Field                      | Description                                                                                                    |
| -------------------------- | -------------------------------------------------------------------------------------------------------------- |
| **Litmus Edge Address**    | Hostname or IP address of the Litmus Edge instance. Add `:port` only when Litmus Edge uses a non-default port. |
| **NATS Proxy Port**        | Port for live data streaming. Default: `4222`.                                                                 |
| **Access Account API Key** | Access-account API key with NATS Proxy read access, or the message broker token. |
| **API Token**              | Optional. Enables topic discovery in the query editor.                                                         |

To provision the data source, save this file in the Grafana provisioning directory:

```yaml
apiVersion: 1
prune: true

datasources:
  - name: Litmus Edge
    type: litmus-edge-datasource
    access: proxy
    editable: true
    jsonData:
      externalEdge: true
      edgeUrl: $EDGE_URL
      natsProxyPort: $EDGE_NATS_PROXY_PORT
    secureJsonData:
      brokerToken: $EDGE_ACCESS_ACCOUNT_TOKEN
      apiToken: $EDGE_API_TOKEN
```

::::
:::::

Save the file as `litmus-edge.yml` in `/etc/grafana/provisioning/datasources/`, or use your configured provisioning path. Set the variables in the Grafana service environment, then restart Grafana. Use a different data source name if **Litmus Edge** already exists in the same Grafana organization.

### Verify Your Setup

1. On the data source settings page, click **Save & test**. Grafana shows `Connected to the Edge`. With an API Token set, the message ends with `Topic discovery is working.` Without one, it ends with `Tip: add an API Token to enable topic discovery.`
2. Add a panel to a dashboard and select the **Litmus Edge** data source.
3. In the **Topic** field, enter the NATS topic of a data point that is publishing, for example `devicehub.alias.demo.bearing_temperature`. With an API Token set, you can instead search for a topic and select it.
4. Watch the panel. Values refresh about once per second while the topic is publishing.

The topic must be an exact NATS subject. Wildcards (`*` and `>`) are not supported. If the panel stays empty, see **Troubleshooting**.

### Remove Litmus Grafana

For the standalone image:

1. Export any dashboards you want to keep. Removing the container and its anonymous volumes deletes its Grafana data.
2. Run `docker rm -fv litmus-grafana`.
3. Run `docker image rm litmusedge.azurecr.io/litmus-grafana:0.2.1` if no other container uses the image.
4. Run `docker ps -a --filter name=litmus-grafana`. The removed container no longer appears.

For an existing Grafana instance:

1. Remove any test panels or dashboards you created for this setup. If you added the data source in Grafana, open its settings and delete it. If you provisioned it with the example above, delete `litmus-edge.yml`. Grafana removes the provisioned data source at the next restart.
2. Run `grafana cli plugins remove litmus-edge-datasource`, or delete the extracted `litmus-edge-datasource` directory from your Grafana plugins directory.
3. Remove the downloaded ZIP with the same account that copied it to the host or container. Remove any Grafana environment or signature settings you added only for this plugin.
4. Restart Grafana. Confirm the data source and plugin are no longer listed.

For either path, revoke any Access Account or API token you created only for this installation. If you created a simulator device only for verification, remove the device and its tags.

## Troubleshooting

| Symptom                                                               | Cause and fix                                                                                                                                                                    |
| --------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Save & test** fails and Grafana runs inside Litmus Edge             | **Edge Docker Gateway IP** is wrong for this instance, or the Grafana container cannot reach Litmus Edge on port `4222`. Check the IP and the container network.                 |
| **Save & test** fails and Grafana connects to an external Litmus Edge | Litmus Edge is not reachable on the configured **NATS Proxy Port**, the NATS Proxy is disabled, or the **Access Account API Key** is invalid. Check each in that order.          |
| The panel shows no data                                               | The topic is not an exact NATS subject, or no device is publishing to it. Remove any wildcard, confirm the device publishes, and look for `Topic not found` in the Grafana logs. |
| The panel shows old values after a reconnect                          | NATS can buffer messages while Grafana is disconnected. Refresh the dashboard to clear them.                                                                                     |
| The Grafana logs show `Messages dropped (buffer full)`                | The topic produced more than 10,000 messages between updates. Query a more specific topic.                                                                                       |

To rotate a token set in Grafana, edit the data source, enter the new value, and click **Save & test**. If you supply the token through provisioning, update its environment variable as well. Grafana stores tokens in secure JSON data and does not return them to the browser.
